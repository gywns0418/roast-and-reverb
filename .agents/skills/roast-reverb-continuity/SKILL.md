# Roast & Reverb continuity

Read the repository's [continuity](../../../docs/continuity.md) and current Git state before continuing implementation. Its theme is coffee records paired with actual music listening records. Preserve this theme and the existing React/Vite + Spring structure unless the user changes the scope.

For coffee work, read [record rules](../../../docs/coffee-records.md) and only the relevant authorized source records in the sibling coffe_brew_log folder. Preserve explicit dates, hours, units, missing values and provenance. Keep water input separate from beverage output and individual pours separate from cumulative pours. Do not infer unrecorded tracks, numeric taste ratings, stock consumption or causes from one cup. Owner preferences are not universal defaults for all members.

For hosting, tools or external research, read [tooling and research](../../../docs/tooling-and-research.md). Verify current connection and deployment state before saying a service is live. Reuse existing projects; no duplicate creation or paid-plan upgrade is implied by this skill. Respect the user's existing authorizations and allowed cost limits.

Before handing off, update [change history](../../../docs/change-log.md) and continuity with the actual changes, meaningful checks, Git/PR/deployment status, limitations and any required user action. Link authoritative sources near the claims they support. Keep secrets and raw personal logs out of the documents and public seed data.
