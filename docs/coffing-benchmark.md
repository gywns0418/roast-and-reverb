## Coffing은 어떤 앱인가

카페를 "원하는 커피와 분위기"로 찾는 지도 앱이다. 리뷰와 SNS 글을 미리 읽어 두었다가, 사용자가 말로 원하는 조건을 말하면 맞는 카페를 보여 준다는 것이 핵심 약속이다("SNS 뒤질 필요 없이").

| 패턴 | Coffing에서 본 것 |
|---|---|
| 말로 찾기 | 첫 화면 한가운데 검색창 하나. "공부하기 좋은", "테라스 있는", "정원이 예쁜 카페 찾아줘" 같은 예시가 돌아가며 보인다 |
| 한눈에 보이는 배지 | 지도 핀에 H(핸드드립)·E(에스프레소)·L(라떼) 글자, 커뮤니티 추천은 "Pick!" 말풍선 |
| 빠른 필터 | 검색창 바로 위에 정렬(추천순)과 칩(커뮤니티 Pick, 핸드드립, 에스프레소, 라떼)이 가로로 늘어서 있다 |
| 지도 ↔ 목록 | 아래쪽에 "27개" 목록 손잡이, 지도와 목록을 오간다 |
| 저장 | 카페 카드에 북마크 버튼 |
| 함께 채우기 | 카페 제보, 정보 수정, 사진 등록, "내 기여"에서 반영 상태 확인 |
| 숫자로 신뢰 | "카페 5,947곳 · 커뮤니티 픽 1,791곳 · 2026년 10월 기준" |

## Roast & Reverb와 비교

Roast & Reverb는 "좋았던 커피, 다음에도 고를 수 있게" 하는 개인 기록장이고, Coffing은 장소 탐색 앱이다. 그대로 옮길 기능은 지도·제보가 아니라 **"원하는 맛을 말로 찾는 방식"**과 **"한눈에 보이는 배지"**다.

| Coffing 패턴 | Roast & Reverb 이전 상태 | 적용 |
|---|---|---|
| 말로 찾기 + 예시 | 월픽 검색은 입력한 글자가 그대로 들어 있는지만 봤다. "산미 적고 고소한"은 0종 | **적용**: 맛 표현 이해, 예시 칩, "이렇게 찾고 있어요" 표시 |
| H/E/L 배지 | 로스팅 정도는 상세 창을 열어야 보였다 | **적용**: 카드에 로스팅·디카페인 배지 |
| Pick! 배지 | 관심 저장 여부는 카드 아래 버튼에서만 보였다 | **적용**: 카드 위쪽에 "♥ 관심" 배지 |
| 빠른 필터 칩 | 모바일에서는 "필터 펼치기"를 눌러야 분류·색상이 보였다 | **부분 적용**: 맛 예시 칩은 접지 않고 항상 보인다 |
| 지도·제보·숫자 신뢰 | 해당 없음 | 적용하지 않음 (장소 서비스가 아님) |

## 이번에 만든 것

`frontend/src/utils/tasteQuery.js`

- "산미 적고 고소한", "꽃향 나는 가벼운", "초콜릿 같은 묵직한", "상큼한 베리", "디카페인" 같은 짧은 표현을 읽는다.
- 근거는 판매처 자료뿐이다.
  - 산미·바디감·발효도: 판매처 향미 지표(1~5). 2 이하 = 낮음, 4 이상 = 높음
  - 고소함·초콜릿·달콤함·베리·시트러스·과일·꽃향·차·와인·깔끔함: 판매처 컵노트에 들어 있는 단어 묶음
  - 로스팅·디카페인: 판매처 로스팅 표기와 디카페인 표시
- 지표가 없는 원두는 지표 조건에서 빠지고, 화면에 그 사실을 적는다.
- 해석하지 못한 단어는 예전처럼 글자 검색으로 남는다. "에티오피아", "복숭아" 같은 검색은 결과가 바뀌지 않는다.
- 서로 반대인 표현("산미 있고 산미 없는")은 결과를 0종으로 만들지 않고 앞의 것을 따른다.

월픽 화면

- 검색 제목을 "맛이나 원두로 찾기"로 바꾸고, 예시를 placeholder와 칩 5개로 보여 준다. 칩을 다시 누르면 해제된다.
- 해석 결과를 "이렇게 찾고 있어요" 칩으로 보여 주고, 판매처 자료 기준이라는 점을 함께 적는다.
- 카드에 분류·로스팅·디카페인·관심 배지를 한 줄로 보여 준다.

## 하지 않은 것과 한계

- AI 모델이나 외부 서버를 쓰지 않았다. 규칙 기반이라 사전에 없는 표현(예: "스모키한")은 글자 검색으로만 처리된다.
- 판매처 지표와 컵노트는 판매처의 설명이다. 내가 실제로 느낀 맛과는 다를 수 있다.
- 내 기록(좋았던 커피)을 바탕으로 월픽을 골라 주는 기능은 다음 후보로 남긴다. Coffing의 "커뮤니티 Pick"에 해당하는 개인판 "내 Pick"이다.
