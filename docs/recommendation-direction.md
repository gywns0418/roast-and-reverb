# 원두 중심 이미지와 발견형 추천 방향

2026-10-13 / Asia/Seoul. 사용자가 현재 연출 사진의 인위적인 느낌과 선택식 페어링의 한계를 지적하고 대안/음악 외부 정보/beans.md/월픽 후보 확대를 요청했다. 이번 단계는 구조 확인과 방향 조사이며 새 화면이나 연결을 완료한 상태가 아니다.

## 이미지

현재 컵·장비·소품 사진을 원두 목록 전체에 반복하는 방식은 원두 개별성을 드러내지 못한다. 월픽 색감과 분류색은 유지한다. 원두 카드에는 원두만 단색 배경에서 찍은 절제된 실제 매크로 사진, 직접 촬영한 사진, 사용 권한이 확인된 로스터리 사진을 우선한다. 로스팅/품종별 모습을 검증하지 않고 특정 상품 실사로 표시하지 않는다. 원두 사진을 확보하기 전에는 원문 팔레트 + 원두 번호/산지/품종의 정보 중심 카드가 더 명확하다. 브랜드 연출 사진은 홈의 대표 영역에 한정하는 방향을 제안한다. 이번 조사에서 판매처 사진을 복사하거나 새 AI 이미지를 생성하지 않았다.

## 현재 분석 범위

R&R v1은 등록한 커피/음악 기록의 규칙 기반 의미 특성과 소형 피드백 모델을 비교한다. 자연어를 이해하는 LLM이나 새로운 곡을 찾는 음악 검색 엔진이 아니다. 추천 페이지의 일부 데이터는 예시다. 채팅 형태만 추가해도 이 한계가 해결되지는 않는다. 후보 수집 → 의미/취향 비교 → 개인 피드백 재정렬 → 설명/재생으로 기능을 나눠야 한다.

## 후보 확대

1. 내 원두: beans.md를 사용자가 브라우저에서 가져오기/검토해 기기 저장소에 저장한다. 기존 coffe_brew_log 원본은 읽기만 했으며 수정/복사/공개하지 않았다. 구조에는 원산지·품종·가공·로스팅일·상태·남은 양/근거가 있다. 개별 원두명, 개인 메모, 수량을 공개 문서/시드에 싣지 않는다. 본래 추출 기록 합산 추정치와 실측/미확인을 구분하고 소진 임박을 소진으로 오인하지 않는다. 서버 모드에서는 회원별 비공개 원두 재고로 관리할 수 있으나 현재 서버는 미배포다.
2. 이달의 원두: 공개 월픽 52종을 구매/발견 후보로 사용한다. 내 보유 원두와 구분해 아직 가진 원두라고 표시하지 않는다. 두 후보 모두 실제 추출/청취 기록을 자동 생성하지 않는다.
3. 음악: 접근 가능한 YouTube 재생목록/곡 링크와 실제 검색 결과를 후보로 사용한다. MusicBrainz의 식별자/장르/태그 등 존재하는 메타데이터를 보완할 수 있다. 없는 BPM/키/악기/음향 특징을 영상 제목만으로 실제 측정치처럼 만들지 않는다.

## 추천 흐름 제안

홈에서 지금 마실 보유 원두 또는 관심 월픽을 골라 짧은 상황을 입력한다(예: 늦은 밤, 일할 때). 음악의 시작점은 사용자가 고른 플레이리스트/좋아하는 곡이다. 그 안에서 맞는 음악을 우선 추천하고, 취향과 가까운 새로운 곡을 별도 탐색 후보로 제공한다. 목록 대신 먼저 조합 3개와 각각의 근거/출처/음악 링크를 보여준다. 반대로 곡 링크에서 보유 원두를 추천하는 흐름도 제공한다. 유사도만 높이는 대신 익숙한 조합/새 발견/대비되는 조합을 함께 제공하는 것은 제품 설계 제안이며 검증된 추천 효과라고 주장하지 않는다.

자연어 문맥 이해는 실제 언어 모델 연결이나 적절한 로컬 모델이 필요하다. 음악 후보 검색과 추천의 근거를 분리하고, 언어 모델은 확인된 사실만 설명하게 한다. 유료 모델 호출을 기본으로 도입하지 않고 무료 한도/로컬 실행 가능성과 품질을 검증한 뒤 선택한다. 개인 원본을 외부 AI로 전송하는 방식은 이번 단계에서 실행하지 않았다.

## YouTube 공식 경계와 준비 조건

- YouTube Data API search.list: 공개 동영상 검색. playlistItems.list: 접근 가능한 재생목록의 항목 조회. 외부 음악 후보는 기존 등록 기록으로 제한할 필요가 없다.
- 공식 API로 사용자의 watch history/watch later는 접근할 수 없다. YouTube Music의 개인 추천 피드가 일반 개발자에게 그대로 제공되는 것처럼 약속하지 않는다.
- Google API 프로젝트/활성화/API 키 및 비공개 접근 시 OAuth 연결이 필요하다. 현재 실제 연결/인증/키 설정을 수행하지 않았다. 공식 무료 할당량과 캐싱을 우선하며 승인되지 않은 유료 전환은 하지 않는다. 브라우저 공개 빌드에 개인 토큰이나 서버 비밀키를 넣지 않는다.
- 제목·채널·길이·썸네일은 실제 응답 범위 내에서 사용할 수 있지만 음원 분석 특징과 다르다. 음악 식별/메타데이터 결합은 별도 단계다.

## 구현 순서 제안

원두 중심 카드 → 내 원두 비공개 가져오기 + 월픽 후보 통합 → 접근 가능한 플레이리스트 후보 연결 → 상황 입력/개인화 추천 → 피드백/다양성 평가. 이미지 교체/가져오기/YouTube 연결/새 추천 모델은 아직 구현하지 않았다. 보유 원두를 먼저 활용하면 구매 없이 즉시 써볼 수 있어 서비스의 첫 사용 경험에 유리하다는 제품 판단이다.


## 2026-10-14 구현 상태

feature/bean-discovery에 원두 파일 미리보기/기기 저장/수정/백업, 보유·월픽·통합 후보, 음악 링크/TSV/백업 가져오기, 자연어 상황의 실제 임베딩 추천을 구현했다. 개인 beans.md를 공개 시드로 만들지 않는다. 원두는 보유 상태만 기본 후보로 사용하고 배송·소진·미확인은 제외한다. 남은 양의 원문과 추정/실측/미확인을 유지한다.

브라우저 worker의 Xenova/multilingual-e5-small q8 모델(고정 revision 761b726dd34fb83930e26aab4e9ac3899aa1fa78)로 문장 임베딩을 계산한다. 사전 학습된 공개 모델 사용이며 새로 학습한 LLM이나 음원 분석기가 아니다. 첫 실행에 공개 모델/WASM 다운로드 및 브라우저 캐시가 필요하며 사용자 입력 문장은 로컬 추론한다. 모델 오류 시 성공 결과를 꾸미거나 기본 추천으로 자동 대체하지 않는다. 기본 규칙 추천은 별도 버튼이다.

실서버용 MusicBrainz 공개 메타데이터 검색과 YouTube 검색/영상/공개 재생목록 API를 구현했다. Pages에서는 서버가 없어 자동 조회할 수 없고 곡명·링크/목록 추가는 가능하다. 계정 청취 이력은 읽지 않는다. YouTube 키는 서버 환경변수 YOUTUBE_API_KEY만 사용한다. 하루 60 upstream 요청 제한, 12시간 캐시, MusicBrainz 요청 간격 1.1초. 실제 서버 배포와 API 키 설정은 아직 미완료다.

참고: https://huggingface.co/Xenova/multilingual-e5-small / https://huggingface.co/intfloat/multilingual-e5-small (MIT 모델 카드), https://huggingface.co/docs/transformers.js/en/pipelines , https://musicbrainz.org/doc/MusicBrainz_API , https://developers.google.com/youtube/v3/docs/search/list . MusicBrainz 무료 비상업 API 조건과 호출 제한을 따른다. 추천은 알려진 설명의 의미 연관성이고 실제 청취/맛 검증 결과가 아니다.


## 2026-10-14 커피에서 음악을 창작하는 방향

사용자 제안: 커피 작성과 음악 작성을 분리하고 산지/컵노트로 음악 생성. 향미를 음색·악기·리듬의 창작 은유로 옮기는 60~90초 연주곡이 서비스 흐름에 잘 맞는다. 이미 알려진 아티스트의 곡 추천과 새로운 음원 생성을 구분하고, 생성곡은 별도 제작물로 표시한 뒤 실제로 들었을 때만 청취 기록을 만든다. 현재 기존 곡 의미 추천 연결과 규칙 제작 설명만 구현했으며 실제 음원 생성 모델/API는 미연결이다.

Stability 공식 API pricing https://platform.stability.ai/pricing 은 계정 시작 무료 크레딧과 모델별 생성 비용을 명시한다. 무료 웹 사용과 무료 API 호출을 같은 것으로 가정하지 않는다. Suno 무료 output 조건은 https://help.suno.com/en/categories/550145 및 https://www.suno.com/terms 에서 확인했다. 무제한 무료 앱 음악 생성으로 표시하지 않는다. 실제 통합 시 서버 전용 키, 확인된 Trial/Free 잔액 이하 요청 한도, 잔액 소진 시 명시적 중단, 자동 결제/유료 전환 없음이 필요하다. 이번 작업에 계정 생성/키 설정/실제 음악 생성/개인 입력 외부 전송은 없었다.

지속 파일 연결은 https://developer.chrome.com/docs/capabilities/web-apis/file-system-access , https://developer.chrome.com/blog/persistent-permissions-for-the-file-system-access-api , https://developer.mozilla.org/en-US/docs/Web/API/Window/showOpenFilePicker 에 따라 read 전용 handle과 IndexedDB를 사용한다. Chrome/Edge의 HTTPS 환경에서 최초 사용자가 파일을 선택하며 앱이 열려 있을 때만 확인한다. 브라우저 종료/저장소 삭제/권한 취소 시 자동 읽기는 멈추고 다시 연결 또는 권한 허용이 필요하다.
