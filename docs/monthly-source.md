# 언스페셜티 월픽 수집과 자동 갱신

최종 확인: 2026-10-13 / Asia/Seoul. 음악 × 커피 주제를 유지한다.

## 실제 원문과 저장 위치

- [10월 유에프오커피 월픽](https://unspecialty.com/product/detail.html?product_no=901).
- [당월 상품 목록](https://unspecialty.com/product/monthly_pick.html?cate_no=79). 상품 번호를 다음 달에도 901로 고정하지 않는다.
- 상품 HTML의 `usf-general-price-list rel`이 연결하는 공개 JSON에서 원두별 컵노트, 국가/지역, 생산자, 품종, 가공, 로스팅, 판매처 향미 지표와 중량별 가격을 읽는다. 10월 자료는 UFO2/UFO2.json을 사용했다.
- 공개 카탈로그: `frontend/public/data/monthly-picks.json`. 10월 자료에서 굿즈/이벤트 패키지를 제외한 커피 52개를 확인했다. 번호가 없는 블렌드와 드립백도 포함한다.
- 판매처의 장문 마케팅 문구, 리뷰/문의의 개인정보, 이미지 파일은 복사하지 않는다. 사실 필드만 저장하고 긴 소개와 레시피는 원문 링크로 연결한다.

## 수집 명령

저장소 루트에서 실행한다. Node 22 이상, 추가 패키지/AI 키가 필요 없다.

```powershell
# 현재 월픽 목록에서 당월 상품을 발견한다.
node scripts/sync-monthly-picks.mjs
# 사용자가 제공한 특정 링크를 추가/갱신한다.
node scripts/sync-monthly-picks.mjs 'https://unspecialty.com/product/detail.html?product_no=901'
npm.cmd run test --prefix frontend
npm.cmd run build --prefix frontend
```

자료가 바뀌지 않으면 changed:false를 반환하고 파일을 다시 쓰지 않는다. 모든 요청 제품을 검증한 뒤 임시 파일을 원자적으로 교체한다. 이전 월/다른 상품은 보존한다. 실패·빈 원문·구조 변경은 기존 자료를 지우지 않고 실패로 종료한다.

## 링크 가져오기 기능의 범위

- 실제 서버: 인증된 `POST /api/monthly-picks/source`에서 상품 HTML과 공개 JSON을 읽는다. 프론트가 동일한 정규화 함수로 자료를 적용한다. HTTPS 언스페셜티 상세 경로/상품번호와 알려진 자료 호스트만 허용하며 redirect를 따르지 않는다. 임의 서버·localhost·다른 호스트·사용자정보가 있는 URL은 거절한다. 20초 요청 시간 제한과 자료 크기 검사를 사용한다.
- GitHub Pages 체험: 서버가 없는 정적 배포다. 이미 수집한 상품 링크는 공개 JSON에 직접 접속해 원두/가격 자료를 갱신할 수 있다. 새 상품의 HTML을 임의로 읽는 기능은 브라우저 CORS 제한 때문에 제공하지 않는다. 새 링크는 이 대화 또는 위 CLI로 수집해 공개 카탈로그에 추가하거나 실제 서버 모드에서 사용한다. 지원하지 않는 링크를 성공했다고 표시하지 않는다.
- Pages에서 JSON만 갱신했을 때 상품 HTML의 재고 확인 시간은 기존 시각을 유지하고, 원두 자료 갱신 시각을 따로 표시한다.
- 기존 직접 입력 월픽과 회원별 저장 기능은 내 월픽 노트 영역으로 보존했다. 관심 원두는 이 기기의 localStorage에 저장되며 기기 간 동기화 기능이라고 표시하지 않는다.

## 정확성 규칙

1. 상품 옵션의 실제 재고/판매 상태만 사용한다. 알려진 재고가 없으면 재고 미확인. 아직 오픈 전이면 오픈 예정. 품절/예정/미확인을 구분한다.
2. 오픈일은 원두 이름의 [10.5 오픈] 등 명시 표기와 카테고리별 일정에서 읽는다. 다른 상품 그룹의 일정으로 덮어쓰지 않는다.
3. 상품 전체의 기본 판매가를 모든 원두에 적용하지 않는다. 원두별 중량·가격을 쌍으로 보존한다. 상품 옵션의 수량은 개인 원두 재고가 아니므로 coffe_brew_log 재고를 변경하지 않는다.
4. 판매처 컵노트와 향미 지표는 개인 관찰/평점과 별도다. 이를 커피 로그나 음악 기록으로 자동 생성하지 않는다. 디카페인/다크 선호는 사용자 필터로 선택하며 발견 카탈로그에 고정 취향 점수를 만들지 않는다.
5. 원두 번호/이름 기반 식별자는 목록 순서 변경에도 유지한다. 시각 그래픽과 브랜드 연출 이미지는 실제 원두 사진/공식 앨범 커버가 아니다.
6. 외부 HTML과 스크립트는 실행하지 않는다. 큰 재고 문자열은 Java의 재귀 정규식 대신 선형 문자열 파서로 읽어 stack overflow를 방지한다.
7. 로봇 규칙과 사이트 공개 경로를 준수한다. 로그인·구매·장바구니·비공개 API 접근을 하지 않는다.

자동 작업은 최신 인수인계/Git을 확인하고 격리 feature 브랜치에서 수집·검증·커밋·dev PR/검사 후 병합·Pages 확인을 진행한다. main은 병합하지 않는다. 값이 같으면 조용히 종료하고 새 자료·실패·필요한 조치만 알린다. Pages workflow와 환경에 feature/monthly-refresh-* 브랜치를 허용했다. 원문이 아직 당월 상품을 공개하지 않았으면 이전 월을 유지하고 보고한다.

## 2026-10-13 원문 색상과 전체 분류 표시

원문 공개 JSON의 item.flavors[].color는 원두별 색감 팔레트다. normalizeMonthlySource가 flavorColors에 6자리 HEX만 안전하게 보존한다. 기존 한국어 컵노트 필드는 그대로 유지하고 팔레트와 개별 컵노트를 일대일 대응이라고 추정하지 않는다. 카드/상세에 판매처 색감으로 표시하며 색 없는 원두는 미기재로 남긴다. 상품 이미지는 복사하지 않았고 자체 생성 연출 이미지를 사용한다.

전체 52개를 언스페셜티 블렌드 5 / 하우스 블렌드 3 / 싱글 18 / 스페셜 싱글 23 / 드립백 3의 색상 구획으로 표시한다. 전체 탭에서도 분류 제목·색띠·배지를 유지한다. 색감 필터는 HEX의 HSL 근사 색군 분류이며 원문 컬러 HEX 자체를 바꾸지 않는다. 검색/분류/구매상태/디카페인/관심/색감은 교집합으로 필터링한다. 수집 CLI로 색상 필드를 추가했고 52개 유지 확인. 원본 재고도 현재 공개 시점에 다시 확인됐다.
