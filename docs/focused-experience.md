# 행동 흐름과 사용성 정리 — 2026-10-16

직접 읽은 근거:
- https://baymard.com/blog/button-design — 동등하게 강조된 여러 버튼이 다음 행동을 모호하게 만든다는 연구. 주요 행동의 스타일·위치·구체적 문구를 구분한다.
- https://www.nngroup.com/articles/progressive-disclosure/ — 기본 작업을 먼저 제시하고 고급·비정기 옵션을 필요할 때 펼쳐 복잡도를 낮춘다.
- https://www.nngroup.com/articles/homepage-design-principles/ — 첫 화면에서 서비스가 주는 가치와 분명한 시작점을 설명한다.

서비스에 맞춰 적용한 판단:
- 추천은 규칙 기반 ‘지금 조합 찾기’ 한 개를 먼저 제시. 문장 의미 AI는 선택 옵션으로 유지, 필요한 첫 모델 다운로드도 펼친 곳에서 설명. 결과로 포커스·스크롤 이동. 각 결과의 주요 행동은 듣기 하나, 근거/감상 기록·평가는 명시적 펼침. 장르 정보 부족 안내 등 중요한 제약은 숨기지 않는다.
- 청음실에서 중복 연주 링크를 없애고 조합 변경과 다른 작업은 상황별 펼침. 세션 시작/음악 열기는 계속 바로 보인다.
- 가이드의 선택적 개인화·음악 준비·별도 일지는 펼침. 노트 저장 피드백은 폼 근처에서도 표시.
- 음악 제작의 AI 대화와 빠른 표현 요청을 별도 펼침으로 분리, 생성·조절·보관의 기본 흐름 유지.
- 홈은 발견/한 줄 기록/다음 선택에 다시 쓰는 구체 효용을 추가. 가격·가짜 할인·가짜 후기·구독 압박 없음.

검증: 주요14경로의 데스크톱/모바일390px 초기 화면에서 페이지 넘침0 및 중첩 interactive0. 추천 실제실행3결과/결과영역포커스/카드당주요링크1 확인. 선택옵션 펼침과 개인화 입력값 보존 확인. JSX77개 정적 구조 검사 이상 없음. 자동 테스트에는 map내 중첩 링크 실제결함 패턴을 탐지하는 AST검사와 전체소스검사를 추가. 커스텀컴포넌트 내부를 넘나드는 모든 조합까지 증명하지는 않는다. 테스트63/build/audit0. 전환 상승은 실제 사용자실험으로 검증할 가설이며 수치 개선을 주장하지 않는다. 과거 기록보유 QA는 이전 dashboard 기록참고, 이번 점검만으로 모든 데이터/오류상태를 확인했다고 주장하지 않는다.
