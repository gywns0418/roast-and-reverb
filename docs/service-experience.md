# 콘텐츠와 실제 이용 경험 / 2026-10-16

사용자는 개인 월 구독을 생각하지만 가격표·결제 화면 구현을 원하지 않는다. 토스페이먼츠는 구상 단계이며 먼저 돈을 낼 이유가 되는 콘텐츠와 편의성을 높이는 것이 현재 요청이다. 계정/결제 자료를 반복 요청하지 않는다.

## 제공한 콘텐츠

/journey의 ‘나의 취향 여정’은 R&R 자체 집필 감상 가이드 7개다. 첫 감각, 시간/온도, 밝기/긴장, 단맛/여운, 질감/리듬, 한 가지 비교, 내 취향 문장으로 구성한다. 각 가이드는 관찰 이유·3단계 활동·개인 질문 3개·돌아볼 관점·기기 연주 설정·기존 음악 추천 진입을 제공한다. 8~15분은 제안 시간이며 날짜 잠금·연속 출석 강요·감각 정답/객관 점수를 만들지 않는다.

발견 노트는 원문 그대로 보존하고 ‘직접 해봄’ 확인과 생각/계획을 구분한다. 같은 가이드를 반복해도 완료 수를 늘리지 않는다. 반복 방문 시 같은 가이드의 이전 말을 보여줘 비교할 수 있으며, 최근12개부터 더 보기로 최대140개에 접근한다. 마지막 취향 문장을 명시적으로 적용할 때만 기존 청음실 문장을 바꾼다(기존 문장이 있으면 확인,600자 초과는 오류). 실제 감상 평점 학습이나 일지로 자동 전환하지 않는다.

## 이용 흐름

홈→취향 여정→기존 곡 선택 또는 가이드 연주→관찰 메모→다시 읽기→명시적 취향 적용→청음실의 다음 추천. 새 브라우저의 예시 커피/음악/페어링/컬렉션을 실제 과거 기록처럼 생성하지 않으며 이미 저장한 자료는 유지한다. 추천은 개인 후보가 없을 때 출처가 표시된 기존 시작 선곡3개로 시작한다.

탐색은 핵심5개와 추가 발견으로 묶었다. 모바일 가로 탐색은 활성 항목을 따라가고 추가 메뉴가 접근 가능하다. /help에서 첫 사용, 추천/연주 차이, 개인화, 저장 위치와 복구를 설명한다. 커피·음악·발견 메모 초안은 계정 범위의 기기에 보존하고 읽기/쓰기 실패를 알린다. 새로운 후보보다 기존 초안 복원을 우선하며 ‘초안 비우기’는 사용자 확인 후 실행한다. 초안·여정·개인 설정은 통합 백업에 포함한다. 로그인 만료 시 토큰만 제거하고 범위 식별자는 보존해 재로그인한 뒤 작성 위치로 돌아올 수 있게 했다.

모든 화면을 개별 로딩해 공통 시작JS 약484KB→280KB(압축 전 빌드 산출물)로 줄였다. 이는 총 다운로드/실제 사용자 체감 시간 측정값은 아니다. 로딩/실패 복구 화면, Enter 로그인/가입, 비밀번호 자동완성, 모달 키보드/네트워크 오류 처리를 보완했다. 이메일 복구가 실제 제공된다는 잘못된 안내는 제거했고 복구 메일 서버를 연결했다고 주장하지 않는다.

## 검증 및 남은 경계

프론트61테스트/build/diff검사, production npm audit0. 로컬 실제 브라우저에서 초안 화면 이동·새로고침 복원, 계획 노트 저장 후 완료0, 취향 문장 적용, guide03→스튜디오 bright/88BPM/.4 설정, 390×844 문서375=scroll375 및 모바일 추가 메뉴 접근 확인. 테스트 노트는 QA용 계획으로 표시했고 실제 마심/청취로 확인하지 않았다. 운영 사용자의 기기 자료는 변경하지 않는다.

월 구독의 가치가 검증됐다고 주장하지 않는다. 정기 콘텐츠 발행/실제 사용자 피드백 검증, 운영 서버/동기화·복구/지원 체계, 사용 데이터 제공자의 상업 이용 조건, 토스 계약·가격/취소/권한 검증은 출시 단계에서 별도로 해결해야 한다. MusicBrainz 공개API의 무료 조건은 비상업 사용이므로 상업 제공 전 [공식 조건](https://musicbrainz.org/doc/MusicBrainz_API)을 확인해야 한다. 결제 구현을 시작할 때는 [토스 공식 흐름](https://docs.tosspayments.com/guides/v2/get-started/payment-flow)의 서버 주문/금액 검증을 따른다. 이번에 유료 서비스·자동 결제·AI 요청·main 승격은 하지 않는다.
